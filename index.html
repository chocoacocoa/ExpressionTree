Code as Data • Runtime Compilation & Inspection

Turn C# Code into an Inspectable Data Tree

Unlike standard delegates that compile straight into opaque IL instructions, Expression<TDelegate> captures your logic as an Abstract Syntax Tree—enabling dynamic SQL generation, runtime mutation, and ultra-fast metaprogramming.

Standard Delegate Executable IL
Func<int, int, int> fn = (a, b) => a + b;

Compiled black-box machine code. Can only be invoked.

Expression Tree Data Structure
Expression<Func<int, int, int>> ex = (a, b) => a + b;

Inspectable node hierarchy. Can be traversed, translated, or compiled.

Two Ways to Build

Lambda Syntax vs. Manual Factory API

Both approaches below produce the exact same expression tree in memory for (a, b) => a + b. Click any highlighted step or line to see what the C# compiler or runtime is doing under the hood.

Approach 1

Compiler-Generated (Lambda)

Best when the expression structure is known at compile time.

using System;
using System.Linq.Expressions;
// 1. Assign lambda to Expression<T>
Expression<Func<int, int, int>> addExpr = (a, b) => a + b;
// 2. Inspect AST nodes at runtime
Console.WriteLine(addExpr.Body.NodeType); // Add
Console.WriteLine(addExpr.Parameters.Count); // 2
// 3. Compile tree into executable delegate
Func<int, int, int> compiledFunc = addExpr.Compile();
// 4. Invoke just like a normal method
int result = compiledFunc(5, 3); // Output: 8
Step 1: Compiler AST Emission

Because the target type is Expression<Func<...>> instead of a plain Func<...>, the C# compiler emits factory calls to build an AST instead of compiling IL instructions.

Approach 2

Manual API Construction

Best when building dynamic queries or rules from user input at runtime.

// 1. Define leaf parameter nodes (a and b)
ParameterExpression paramA = Expression.Parameter(typeof(int), "a");
ParameterExpression paramB = Expression.Parameter(typeof(int), "b");
// 2. Combine leaves into a BinaryExpression body
BinaryExpression body = Expression.Add(paramA, paramB);
// 3. Wrap body & parameters into root Lambda
Expression<Func<int, int, int>> addExpr =
    Expression.Lambda<Func<int, int, int>>(body, paramA, paramB);
// 4. Compile and invoke dynamically constructed tree
var compiled = addExpr.Compile();
Console.WriteLine(compiled(10, 20)); // Output: 30
Step 1: Creating ParameterExpression Leaves

Trees are built bottom-up. First, we instantiate ParameterExpression objects representing the input variables a and b. Note that variable identity is tracked by object reference, not just string name!

Real-World Architecture

Why Use Expression Trees?

Explore how major .NET libraries leverage Expression Trees to translate C# into SQL or eliminate slow reflection overhead.

1. Dynamic Queries (LINQ to SQL)

How Entity Framework translates C# predicates into database SQL

When you pass a lambda to IQueryable<T>.Where(...), EF Core walks the Expression Tree nodes (MemberExpression, BinaryExpression) and visits each node to emit parameterized SQL rather than loading the entire table into memory.

Toggle LINQ Filter Predicate
C# IQueryable Expression:
db.Users.Where(u => u.Age > 18)
ExpressionVisitor Translation
Generated SQL Query:
SELECT [u].[Id], [u].[Name], [u].[Age]
FROM [Users] AS [u]
WHERE [u].[Age] > 18

2. Fast Reflection Alternative

Compile dynamic property accessors & mappers into native IL

Standard PropertyInfo.GetValue() inspects metadata and boxes values on every single call. Serializers (like System.Text.Json) and ORMs (like Dapper) build an Expression Tree once, call .Compile(), and cache the resulting delegate for near-native speed.

1,000,000 Property Reads Benchmark
Direct C# Property (user.Name) ~1.2 ms (1.0x)
Compiled Expression (expr.Compile()) ~1.8 ms (1.5x)
Standard Reflection (propInfo.GetValue) ~145.0 ms (120x slower)
Pro Tip: Cache the compiled Func<T, TProp> in a ConcurrentDictionary—calling .Compile() itself has a one-time setup cost.
